Rather than relying on a single retrieval signal, DocuSearch pulls together three complementary sources of evidence: semantic search over a Qdrant vector store using BGE-Large embeddings, BM25 full-text search over an SQLite FTS5 index, and Knowledge Graph neighbour expansion from a structured edge table. These three ranked lists are merged through Reciprocal Rank Fusion (RRF) with signal weights $w_{v}=0.50$, $w_{b}=0.35$, and $w_{kg}=0.15$, giving:   Equation $$ s_{\mathrm{RRF}}(d)\;=\;\sum_{i\in\{v,\,b,\,kg\}}\frac{w_{i}}{k+r_{i}(d)},\quad k=60 $$   where $r_{i}(d)$ is the rank of chunk $d$ in signal list $i$. A cross-encoder then reranks the fused list, and Maximal Marginal Relevance (MMR) with $\lambda=0.65$ prunes it for both relevance and diversity. What makes DocuSearch distinctive is a per-chunk evaluation loop that treats each selected chunk as its own mini-retrieval problem: an LLM decides whether the chunk needs additional neighbouring context, whether it is actually sufficient to answer the query, and whether the answer it generates is genuinely grounded in the retrieved text. ## Response

## Core technologies

- **Embeddings:** DocuSearch uses **BGE-Large-EN-v1.5** embeddings. The model represents each query as a **1,024-dimensional vector**, and retrieval uses cosine similarity. [3]
- **Vector storage:** These embeddings are stored in a **self-hosted Qdrant** vector store for dense semantic search. [6] Documents are also indexed in **SQLite FTS5** for BM25 keyword search, but SQLite FTS5 is the full-text component rather than the vector store. [1][6]
- **LLM inference:** The system uses the **Mistral** model through either a **local REST endpoint or vLLM**. The overall multi-agent pipeline is orchestrated with **LangGraph**. [6]

## Connection to telecom data privacy

The paper connects this technology choice directly to operational privacy: DocuSearch runs **offline with locally hosted models and makes no external API calls**. [2] This is important because telecom operations contain sensitive network-configuration data that, according to the paper, must not leave the organisation’s infrastructure. [2] The locally hosted Qdrant store, embedding model, and Mistral inference stack therefore support keeping document contents, embeddings, and LLM processing inside that infrastructure. [2][6]

The paper also describes a session-only upload mode in which documents are embedded in memory using a local NumPy array rather than being written to the persistent knowledge base. [6] This provides an additional privacy-oriented handling option for temporary documents.

## What the paper does not clearly specify

The paper does **not clearly specify** concrete security controls such as encryption, access-control policies, retention rules, or whether every deployment uses the same local REST or vLLM configuration. It establishes the architectural privacy benefit of local, API-free processing, but not a complete telecom data-governance or security specification. [2][6]
