## Response

## Four sequential checks in DocuSearch

For each candidate chunk \(c\) in the evidence set, DocuSearch applies these checks in order:

1. **Context Need Detection** — The LLM determines whether the chunk is fragmented and needs its previous or next neighbouring chunks. If necessary, neighbours are fetched and appended for up to two iterations. [1]

2. **Sufficiency Scoring** — The expanded chunk \(\tilde{c}\) must receive a sufficiency score of at least \(\tau=7\) on a 1–10 scale. Chunks below this threshold are skipped. [1][2]

3. **Answer Generation** — For a sufficient expanded chunk, the LLM uses \(\tilde{c}\), the query \(q\), and the selected answer template to generate a candidate answer \(\hat{a}\). [1]

4. **Groundedness Verification** — A separate LLM call checks whether the generated answer is fully supported by the expanded chunk. If it is, the answer is accepted and the per-chunk process terminates. [1]

The first chunk that passes all four checks produces the final answer; if none does, DocuSearch uses a fallback that merges the expanded contexts and performs one final groundedness check. [2]
