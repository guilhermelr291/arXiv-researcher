# SenseNova-U1.5’s near-lossless visual interface

## Pipeline in execution order

1. **Direct pixel-space input**  
   SenseNova-U1.5 accepts either raw images or noise-corrupted visual inputs and converts them directly into visual token sequences, without using an external visual encoder or a VAE. [1]

2. **Spatial downsampling**  
   The image passes through two convolutional projections with GELU activations. These projections downsample the visual input by factors of \(16\) and \(2\), giving a total spatial reduction factor of \(32\). [1]  
   Consequently, the interface produces **one visual token for each \(32\times 32\) image region**. [1] This compact patchification keeps the visual sequence short enough for large-scale multimodal processing. [1]

3. **Spatial organization**  
   Two-dimensional sinusoidal positional embeddings are added so that the model retains the spatial coordinates of the visual tokens. [1] Special `<img>` and `</img>` tokens mark the boundaries of individual visual blocks in the sequence. [1]

4. **Joint multimodal processing**  
   Text is tokenized with the original language tokenizer. [1] The visual and textual representations are then projected into a shared hidden space and processed together by the unified backbone. [1]

## What “near-lossless” means

“Near-lossless” means that the interface aims to preserve the image’s visual information while representing it with a compact sequence of \(32\times 32\)-region tokens. [1] The paper presents this as a compromise between visual fidelity and manageable sequence length, rather than as mathematically exact, pixel-perfect losslessness. [1]

The paper also links the improved information preservation to the **decoding** side of the interface. Earlier SenseNova-U1 decoding reconstructed each visual token as an independent RGB patch, which could cause seams and texture discontinuities at high resolution. [2] SenseNova-U1.5 instead reconstructs tokens jointly in a spatial feature field, allowing neighboring regions to exchange information before the final pixels are produced. [2]

## Decoding path that supports the interface

After the unified backbone produces hidden states, the model restores their two-dimensional topology, converting the sequence representation into a tensor of shape

\mathbf{H}_{2D}\in\mathbb{R}^{B\times d\times h\times w}.

A lightweight spatial decoder then progressively reconstructs the RGB image using Pixel Shuffle upsampling factors of \(2\), \(2\), and \(8\). [3] \(3\times 3\) convolutions are placed between these upsampling stages, allowing neighboring token regions to exchange information and enabling pixels near patch boundaries to be determined jointly. [3] This spatially coupled reconstruction is intended to improve spatial continuity, high-resolution fidelity, and robustness while retaining compact \(32\times 32\) visual tokenization. [1]
